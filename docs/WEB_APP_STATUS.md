# حالة Web App — ما هو منفَّذ وما يحتاج عتادًا

الفرع: `codex/web-app-foundation` — أساس Android: `codex/gps-system` عند `6ff7449`

هذا المستند يقول ما هو **مُنفَّذ ومُختبَر آليًا**، وما **لم يُختبر على لوحة
حقيقية بعد**. القاعدة الحاكمة: لا يُوصف أي مسار عتاد بأنه معتمد قبل تجربته
على متحكم طيران فعلي.

## التشغيل

```bash
npm install
npm run web            # خادم تطوير على http://127.0.0.1:5173
npm run build:web      # بناء إنتاجي إلى dist-web/
npm run preview:web    # معاينة البناء الإنتاجي
npm run typecheck      # فحص أنواع Android
npm run typecheck:web  # فحص أنواع المتصفح
npm run scan:web-bundle  # تدقيق الحزمة الإنتاجية
```

`localhost` يُعدّ سياقًا آمنًا، لذلك يعمل Web Serial أثناء التطوير عبر HTTP
عادي. **أي نشر حقيقي يجب أن يكون على HTTPS** وإلا اختفت واجهات USB من
المتصفح تمامًا.

## متطلبات المتصفح

| المتصفح | MSP / Web Serial | STM32 DFU / WebUSB |
| --- | --- | --- |
| Chrome / Edge (سطح مكتب) | مدعوم | مدعوم |
| Opera (سطح مكتب) | مدعوم | مدعوم |
| Firefox | غير مدعوم | غير مدعوم |
| Safari | غير مدعوم | غير مدعوم |
| Chrome على Android | Web Serial غير متاح | WebUSB متاح جزئيًا، غير مُعلن |

عند غياب أي منهما يعرض التطبيق تنبيه توافق يوضّح **السبب**: متصفح غير مدعوم
أم صفحة غير آمنة (HTTP). الحالتان تبدوان متطابقتين من داخل التطبيق ولهما
حلّان مختلفان تمامًا. لا يُعطَّل فتح ملفات Firmware ولا إعداد Cloud Build في
الحالتين، لأنهما لا يحتاجان أي ناقل.

| القدرة | الحالة على Web | ملاحظة |
| --- | --- | --- |
| البداية والاتصال | منفَّذ | نفس الشاشات العربية |
| اختيار جهاز USB صريح | منفَّذ | لازم في المتصفح: `getPorts()` لا يعرض إلا ما سبق الإذن به |
| MSP عبر Web Serial | منفَّذ — **يحتاج اختبار عتاد** | نفس المحلل والمنسق المشتركين |
| Setup والاتجاه والبطارية | منفَّذ — **يحتاج اختبار عتاد** | لا توجد telemetry مصطنعة |
| مجسم الاتجاه | منفَّذ | SVG بدل Skia، نفس `computeDroneScene` |
| Motors | منفَّذ — **يحتاج اختبار عتاد** | نفس بوابات السلامة بلا استثناء |
| Ports | منفَّذ — **يحتاج اختبار عتاد** | نفس interlock ومنع كسر USB MSP |
| GPS | منفَّذ — **يحتاج اختبار عتاد** | فتح الخريطة عبر OpenStreetMap/HTTPS |
| Configurations | منفَّذ — **يحتاج اختبار عتاد** | نفس الحفظ المتحقق |
| حوارات Alert العربية | منفَّذ ومختبَر | بديل حقيقي لتنفيذ RNW الفارغ |
| فتح ملف HEX/BIN/UF2 | منفَّذ | File Picker في المتصفح |
| حفظ UF2 | منفَّذ | تنزيل متصفح؛ النسخ إلى RP2040 يبقى للمستخدم |
| تنزيل Firmware / Cloud Build | منفَّذ | يخضع لسياسة CORS والشبكة |
| STM32 ROM / ESP عبر Serial | منفَّذ — **يحتاج اختبار عتاد** | عبر نفس `UsbSerialTransportClient` |
| STM32 DFU / DfuSe عبر WebUSB | منفَّذ — **يحتاج اختبار عتاد** | تحليل layout، مسح، كتابة، read-back، manifestation |
| DFU exit / read-unprotect | منفَّذ — **يحتاج اختبار عتاد** | نفس منطق العتبات في Android |
| Receiver / PID | غير معروض | لا يوجد تنفيذ مشترك؛ يظلّان معطّلين كما في Android |

## REQUIRES HARDWARE TEST

لم يُوصَل أي متحكم طيران حقيقي بهذا الفرع. الاختبارات الآلية تجري على أجهزة
وهمية تُحاكي سلوك الواجهات (قفل التدفقات، أخطاء `DOMException`، آلة حالات
DfuSe كاملة)، وهي **لا تُغني** عن التجربة الفعلية. المطلوب قبل اعتماد إصدار:

1. **Web Serial:** اتصال، تعريف اللوحة، telemetry حيّة، قراءة/كتابة/قراءة
   راجعة في Ports وGPS وConfigurations.
2. **Motors:** إيقاف المحركات على كل مسار مغادرة (تبديل تبويب، رجوع، فصل
   كابل، إغلاق التبويب).
3. **تغيير baud أثناء الجلسة:** Web Serial لا يملك تغييرًا حيًّا للسرعة، لذلك
   ينفَّذ إغلاقًا وإعادة فتح. بعض اللوحات تعامل ذلك كإعادة تشغيل — هذا أهم
   فرق سلوكي عن Android ويجب التحقق منه على لوحة.
4. **تجارب فشل:** رفض الإذن، فصل الكابل أثناء القراءة أو الكتابة، منفذ مشغول
   من تبويب آخر، عدم تطابق Target.
5. **WebUSB DFU:** إذن صريح، قراءة layout من bootloader فعلي، مسح انتقائي
   وكامل، كتابة، read-back verify، فصل أثناء العملية، exit، read-unprotect.

## فروق سلوكية حقيقية عن Android

- **`setBaudRate` إغلاق وإعادة فتح.** Web Serial يثبّت السرعة عند `open()`.
  معرّف الجلسة ومشتركوها وحالة الاستقبال تبقى، لكن المنفذ الفيزيائي يُغلق
  ويُفتح فعلًا.
- **لا يوجد `wTransferSize` في DFU.** WebUSB لا يكشف الواصفات الخام، فيُستعمل
  2048 وهو ما يرجع إليه Android أصلًا. لوحة تعلن حجمًا أصغر سترفض الكتابة
  بخطأ حقيقي، لا بتلف صامت.
- **لا يوجد timeout لنقل التحكم في WebUSB.** كل حلقة انتظار محدودة بعدد
  دوراتها، والتفليش محدود إضافيًا بعلم الإلغاء.
- **لا اسم منتج في Web Serial.** يُترك الحقل فارغًا بدل تخمينه.
- **لا Service Worker.** أداة تفليش تخدم نفسها من ذاكرة مؤقتة قديمة تعني أن
  المشغّل قد يفلّش من نسخة لم يخترها.
