## 1 — كيف تُلتقط القيم الخام، وما الذي لا يمكن التقاطه

هذه أهم فقرة عملية في المستند، لأن §2 يطلب مقارنة أربع طبقات:

```
raw MSP → decoded → semantic state → UI
```

**الطبقة الخام غير متاحة في البناء المُصدَّر.** لوحة الـserial الخام
(`UsbSerialDebugPanel`) محجوبة خلف `__DEV__` عبر `src/ui/screens/debugPanels.ts`،
و`scripts/scan-production-bundle.js` يفشل البناء إن تسربت. أي أن APK
الإصدار وبناء الويب الإنتاجي **لا يعرضان بايتات MSP إطلاقًا**، وهذا
سلوك مقصود لا عيب.

لذلك أمامك مسارا التقاط، والأول يكفي للحكم:

### المسار أ — تقاطع مستقل عبر CLI (البناء المُصدَّر، موصى به)

شاشة `سطر الأوامر` تُشحن. أوامر `get` تقرأ القيمة من **البرنامج الثابت
نفسه كنص**، ولا تمر بأي decoder من عندنا. اتفاق شاشة تسجيل الرحلات مع
مخرجات CLI هو دليل حقيقي على أن سلسلة فك الترميز صحيحة، لأن المصدرين
مستقلان.

الأسماء أدناه مقروءة من `src/main/cli/settings.c` عند الالتزام المثبّت
`7348054f` (API 1.47) — ليست تخمينًا:

```
get blackbox_device
get blackbox_sample_rate
get debug_mode
get blackbox_disable_pids
get blackbox_disable_rc
get blackbox_disable_setpoint
get blackbox_disable_bat
get blackbox_disable_mag
get blackbox_disable_alt
get blackbox_disable_rssi
get blackbox_disable_gyro
get blackbox_disable_gyrounfilt
get blackbox_disable_acc
get blackbox_disable_attitude
get blackbox_disable_debug
get blackbox_disable_motors
get blackbox_disable_servos
get blackbox_disable_rpm
get blackbox_disable_gps
```

**انتبه لقلب المعنى:** اسم الإعداد `disable`. القيمة `ON` تعني الحقل
**مستبعد**، والشاشة تعرض «تضمين الحقل» مطفأً. هذا ليس تناقضًا، بل هو
بالضبط التحويل الذي تجريه `blackboxFieldIncluded` مرة واحدة.

**إعدادان يظهران في CLI ولا تملكهما الشاشة:** `blackbox_mode` و
`blackbox_high_resolution`. ليسا في حمولة `MSP_BLACKBOX_CONFIG` الـ11
بايت إطلاقًا، فلا تتوقع رؤيتهما في الواجهة ولا تعدّه نقصًا.

> **حذار من `dump`/`diff`:** الخروج من شاشة CLI بعد جلسة كتابة يعيد
> تشغيل المتحكم في هذا التطبيق. للقراءة فقط استخدم `get` واخرج بلا حفظ.

### المسار ب — البايتات الخام (بناء `__DEV__` فقط)

إن أردت الطبقة الخام فعلًا، شغّل بناء تطوير (`npm run web` أو APK
debug)، وافتح لوحة الـserial، والتقط إطارات الأوامر:

| الأمر | الرقم | الطول المتوقع |
|---|---|---|
| `MSP_BLACKBOX_CONFIG` | 80 | 11 بايت |
| `MSP_DATAFLASH_SUMMARY` | 70 | 13 بايت |
| `MSP_SDCARD_SUMMARY` | 79 | 11 بايت |
| `MSP_ADVANCED_CONFIG` | 90 | 20 بايت |

فُكّها يدويًا بحسب العقد الموثّق في `decodeBlackboxConfig.ts` وأخواتها،
وقارن. **لا تستخدم decoder التطبيق لتوليد القيمة المتوقعة** — ذلك
يجعل الاختبار دائريًا.

## 3 — حقيقة الذاكرة الداخلية (بلا كتابة)

| الحالة على اللوحة | المتوقع في الواجهة | لُوحظ | التصنيف |
|---|---|---|---|
| supported=1، ready=1، used=0 | «فارغة» + `0 بايت مستخدم من <السعة>` | | |
| supported=1، ready=1، used>0 | «تحتوي سجلات» + used/total + شريط | | |
| supported=1، ready=0 | «الذاكرة الداخلية مشغولة الآن» — **بلا أي أرقام** | | |
| supported=0 | لا بطاقة ذاكرة داخلية إطلاقًا | | |

**ممنوع:** أن يظهر used=0 كـ«غير موجودة»، أو أن تظهر أرقام تخزين
بجانب ready=0.

## 4 — حقيقة كرت SD

نفّذ فقط إذا كانت اللوحة تملك فتحة SD.

| الخطوة | المتوقع | لُوحظ | التصنيف |
|---|---|---|---|
| كرت مركّب، النظام جاهز | `READY` ثم — وفقط عندها — تظهر السعة | | |
| **افصل الطاقة**، انزع الكرت، أعد التشغيل، أعد القراءة | «لا يوجد كرت SD»، **ولا `0 MB`** | | |
| تهيئة ملحوظة طبيعيًا (إن حدثت) | `CARD_INITIALIZING` / `FILESYSTEM_INITIALIZING` | | |

> انزع الكرت والطاقة مفصولة. ولا تُحدث تلفًا متعمّدًا في نظام الملفات
> لاختبار `FATAL`؛ تلك الحالة تُترك `NOT EXECUTED` ما لم تظهر تلقائيًا.

**تعريف مهم:** «متاح للتسجيل» في الواجهة هو أكبر مساحة **متصلة**
(`afatfs_getContiguousFreeSpace`)، لا مجرد فارغ − مستخدم. على كرت مجزّأ
سيكون أقل من توقّعك، وهذا صحيح لا خطأ.

## 5 — الحفظ: تغيير واحد آمن وقابل للعودة

غيّر **حقلًا واحدًا فقط**، ويُفضَّل `sampleRate`.

| # | الخطوة | المتوقع | لُوحظ | التصنيف |

| 5 | `MSP_EEPROM_WRITE` | «جارٍ الحفظ وإعادة التشغيل…» | | |
| 6 | إعادة التشغيل | شاشة إعادة الاتصال | | |
| 7 | جلسة جديدة موثّقة | | | |

## 9 — المسح على العتاد (متلف للبيانات)

> **بوابة:** لا تنفّذ إلا إذا (أ) السجلات الموجودة يمكن الاستغناء عنها،
> (ب) **أكّد المالك ذلك صراحةً**، (ج) الوجهة المحفوظة = FLASH، (د) flash
> جاهزة، (هـ) used > 0.

سجّل قبل المسح: `used = ____` / `total = ____`

| # | الخطوة | المتوقع | لُوحظ | التصنيف |
|---|---|---|---|---|
| 1 | تأكيد واحد | حوار واحد، زرّان | | |

| 4 | الاستطلاع ≈ 500ms | | | |

| 6 | ready=false مؤقتًا | «جارٍ مسح الذاكرة…» لا فشل ولا فراغ | | |

## 11 — الرفض الصامت للكتابة

`blackboxMayEditConfig()` = `blackboxState <= BLACKBOX_STATE_STOPPED`،
أي أن المتحكم يبتلع الكتابة ويردّ ACK عاديًا أثناء التسجيل الفعلي.

إدخال اللوحة في حالة تسجيل نشط يتطلب تسليحًا، والتسليح على المنضدة خارج
نطاق هذا المستند. **لا تحاول إجباره.**

الحالة: `HARDWARE SILENT-REJECTION PATH NOT EXECUTED`. المسار البرمجي
مثبت بالفعل باختبار لوحة افتراضية تبتلع الكتابة وترد ACK.
